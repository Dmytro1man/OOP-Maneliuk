 Опис реалізації

У цій лабораторній роботі реалізовано обробку мережевих помилок та помилок вводу/виводу за допомогою патерну Retry[cite: 33]. 
Відповідно до варіанту 15, імітовано процес завантаження файлу конфігурації[cite: 35]. Метод `LoadConfiguration` (клас `FileProcessor`) імітує викидання `IOException` перші 2 рази, а `DownloadConfiguration` (клас `NetworkClient`) імітує `HttpRequestException` перші 3 рази[cite: 35]. Клас `RetryHelper` успішно перехоплює ці винятки завдяки делегату `shouldRetry` та здійснює повторні виклики з використанням експоненційної затримки, поки операція не завершиться успішно[cite: 33].

**Висновок щодо експоненційної затримки:** 
Експоненційна затримка дозволяє уникнути перевантаження системи (наприклад, сервера) під час збоїв, оскільки кожна наступна повторна спроба відбувається через вдвічі більший проміжок часу, даючи системі час на відновлення[cite: 33].



 Відповіді на контрольні запитання

**1. Які типи винятків найчастіше виникають при роботі з файлами та мережею?**
При роботі з файлами (ввід/вивід) найчастіше виникають винятки `IOException`, `FileNotFoundException` та `DirectoryNotFoundException`[cite: 33]. При роботі з мережею типовими є `HttpRequestException` та `SocketException`[cite: 33].

**2. Поясніть принцип роботи патерну Retry. Коли його доцільно використовувати?**
Патерн Retry — це стратегія автоматичного виконання повторних спроб для операції, яка завершилася помилкою[cite: 33]. Його доцільно використовувати для "тимчасових" (транзієнтних) помилок — наприклад, коли пропало з'єднання з мережею або файл тимчасово заблокований іншим процесом[cite: 33]. Якщо помилка постійна (наприклад, невірний пароль), цей патерн не використовується.

**3. Як реалізувати експоненційну затримку між повторними спробами?**
Експоненційна затримка реалізується шляхом множення початкового часу очікування на ступінь двійки з кожною новою спробою (формула `initialDelay * 2^retryAttempt`)[cite: 33]. У C# це можна зробити за допомогою `Thread.Sleep(TimeSpan.FromMilliseconds(initialDelay * Math.Pow(2, attempt)))`.

**4. Для чого потрібен делегат shouldRetry у допоміжному класі RetryHelper?**
Делегат `shouldRetry` типу `Func<Exception, bool>` необхідний для вибіркової обробки винятків[cite: 33]. Він дозволяє визначити, чи має сенс повторювати операцію при конкретному типі помилки (наприклад, перехоплювати лише `IOException` або `HttpRequestException`, а при критичних помилках на кшталт `NullReferenceException` — одразу переривати роботу)[cite: 33].
